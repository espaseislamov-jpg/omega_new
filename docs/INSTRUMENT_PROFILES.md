# Профили приборов и колонок

Профиль хранит пять вещей:

- название прибора или колонки;
- ожидаемое время выхода каждой из 15 кислот;
- один множитель итогового Omega-3;
- схему расчёта Omega-3;
- список пиков, площади которых входят в числитель прямой схемы.

Встроенный профиль `118 прибор` неизменяем и сохраняет совместимую
формулу расчёта. Для нового прибора следует создать
его копию, внести RT и только затем сделать копию активной.

## Работа в интерфейсе

Кнопка `Профили приборов…` открывает менеджер. В нём можно создать или
скопировать профиль, изменить название, RT, схему расчёта, пики числителя и множитель, удалить неактивный
профиль, а также импортировать и экспортировать профиль. Двойной щелчок по
строке кислоты открывает ввод RT.

Активный профиль виден в верхней панели. При его смене уже открытый батч
полностью пересчитывается последовательно; смешивать результаты разных
профилей в одном загруженном батче программа не позволяет.

## Передача коллегам

Кнопка `Экспорт` создаёт один файл `*.omega-profile.json`. Он содержит все RT,
формулу, пики числителя, множитель и название, не зависит от Git и может быть отправлен вместе с новой
версией программы. На другом компьютере файл добавляется кнопкой `Импорт`,
после чего импортированный профиль нужно сделать активным.

Локальная библиотека хранится в `omega_instrument_profiles.json` в каталоге
приложения. Она не включается в Git и не заменяется обновлением программы.

## Численный контракт

Профильные RT используются matcher'ом и локальными C18/C20/C22 стадиями.
Схема `Совместимый Omega v2.7` сохраняет совместимую формулу и все её поправки.
Схема `Прямой расчёт по выбранным площадям` делит сумму выбранных площадей
на полную сумму интегрированных целевых площадей, после чего один раз применяет
профильный множитель.
Множитель не меняет площади, границы, выбор baseline/model и решение судьи.
Он применяется один раз после окончательного выбора результата к отображаемым
полям Omega (`omega3_trio`, strict и corrected). Исходные значения сохраняются
рядом с суффиксом `_unscaled`.

Для пользовательского профиля RT служат опорными значениями, а не жёсткой
разметкой каждой пробы. После первичного поиска программа строит ограниченную
линейную калибровку `observed_rt = slope * profile_rt + intercept`. Поэтому
поправка может постепенно меняться от C16 к C24. При недостатке надёжных опор
используется прежний безопасный общий сдвиг. Неподходящий профиль не имеет
права назначать ближайший далёкий пик вместо отсутствующего.

Четыре нижних окна также рассчитываются по активному профилю и локальной
поправке текущей пробы отдельно для C16, C18, C20 и C22. Их заголовки показывают
фактические границы. В таблице пиков колонка `RT расч.` показывает уже
скорректированный RT текущей хроматограммы.

## Судья относится к конкретному профилю

Новый профиль не наследует проверенные границы судьи старого прибора. Пока для
него не собрана отдельная ручная база, менеджер показывает `Судья: Не настроен`,
а результаты получают действие `ПРОВЕРИТЬ — судья профиля ещё не настроен`
вместо вводящего в заблуждение зелёного статуса.

Для срочной эксплуатации профиль может содержать режим `Экстренный ±0.8`.
Он не переносит абсолютные RT-правила старого прибора: проверка ведётся
относительно динамически скорректированных RT активного профиля и состава его
формулы. `СТОП` означает пропуск или двойное назначение расчётного пика,
`ПРОВЕРИТЬ — экстренно` — подозрительную вершину/границу/форму, а зелёный статус
означает только отсутствие этих грубых признаков. Статистической гарантией
точности такой статус не является.

Изменение RT, формулы расчёта или множителя сбрасывает калибровку судьи.
Экспортированный профиль переносит коллегам также статус и параметры
калибровки. Требования к ручной базе и порядок проверки описаны в
[`JUDGE_PROFILE_CALIBRATION.md`](JUDGE_PROFILE_CALIBRATION.md).
